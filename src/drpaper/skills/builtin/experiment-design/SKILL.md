# 实验设计规范

## 四要素

实验设计章节必须覆盖：数据集、对比方法（基线）、评价指标、实验细节。缺一即在诊断中标记【建议改】。

## 数据集

- 选择标准：任务匹配（基准数据集优先）、规模适中（初学者可复现）、公开可获取
- 每个数据集说明：名称、任务类型、规模、划分方式（训练/验证/测试）
- 引用数据集出处时优先检索文献库中的原始论文

## 对比方法（基线）

至少覆盖两类，并说明选择理由：

1. **经典方法**：该任务长期公认的基线，用于建立参照系
2. **近期方法**：近 2~3 年的代表性工作，用于证明当前先进性

- 基线应与本文方法可比：相同数据划分与评测协议
- 相关工作里归纳出的技术路线，各选 1 个代表进入基线，形成呼应

## 评价指标

- 与任务匹配：分类 → Accuracy/F1；生成 → BLEU/ROUGE + 人工评测；检索 → Recall@K/MRR
- 主指标明确（1~2 个），辅指标按需；只报单一指标应说明理由
- 每个指标一句话说明其含义与选择动机

## 消融实验

- 目的：归因各模块贡献，逐个移除/替换关键模块，观察性能变化
- 至少覆盖方法节提出的 2~3 个核心模块
- 变体命名清晰：如 "w/o 模块名"（去掉该模块）

## 数据分层规范

实验表格中的数值分两类，来源不同：

1. **基线行 = 文献实测**：写表前调用 estimate_metric，返回的 baselines 是文献库里各方法在指定数据集上的实测数字（可溯源至摘要原句），直接引用并标注对应编号 [n]
2. **本文方法行 = 预期区间**：原样使用 estimate_metric 返回的 cell 字符串（如 `83.5~85.2†`），禁止修改数字；返回的 tier 标明证据强度——`exact`（同数据集同指标 ≥3 条实测值）、`cross_dataset`（同指标跨数据集 ≥3 条，分析段必须写明"跨数据集文献实测值"，禁止当作本数据集结论）、`sparse`（仅 2 条，低置信，区间已加宽）；区间下界低于最优基线是刻意设计——真实提升常不如文献报告的乐观
3. **估计失败**：返回 insufficient 或 no_match（按序降级后仍无法估计）时，该单元格写"【待补充：明确说明缺什么】"，如：
   - 【待补充：在 NAT 数据集上与 BERT-base 对比的 F1 值】
   - 【待补充：消融实验结果表】
- 占位需可执行：读到占位句的人应知道去跑什么实验、填什么数

## 防规整原则

- 预期值是区间而非单点，来自文献真实数字的散布，天然不规则；禁止手动"美化"成整数或等差
- 分析段对†区间用"预期 / 有望 / 参考"措辞，禁止"实验结果表明"
- 分析段写明证据强度：精确估计写"基于 X 条同数据集文献实测值"，降级估计如实写"跨数据集参考"或"仅 X 条、置信度低"，禁止把降级区间与精确估计混同表述
- †标记保留到导出，Word 中会黄色高亮并附批注提醒学生替换为实测值

## 严禁

- 禁止不经 estimate_metric 自行写出任何实验数值或"提升 X%"这类伪结果
- 禁止把预期区间改写成单点值

## 结果分析（如有真实数据）

- 结果用三线表呈现：表题行"表 N：标题"紧贴表格上方，正文用"由表 N 可见"引用
- 不只报数：每个结果回答"说明了什么"——表格后必须紧跟分析段，把数字差异归因到方法机制（"这得益于……的设计"）
- 异常结果（某数据集反而变差）应给出假设性解释
