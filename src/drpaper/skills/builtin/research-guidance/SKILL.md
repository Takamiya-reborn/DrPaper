# 研究指导：问方向、荐论文、找接续点

## 第一步：判定意图（三选一）

- **问方向**：用户问某领域/技术"还有什么可做的方向"→ 走方向发散流程。
- **求推荐 / 找接续**：用户想要值得读的论文、想接着别人的工作往下做 → 走论文推荐流程。
- **查新**：用户意图是"这个课题有没有人做过"→ 改加载 novelty-check skill，本 skill 不处理。

## 第二步：咨询检索（不入文献库）

一律调用 search_literature 且 **传 register=false**（咨询结果不登记、无编号，避免污染起草文献库）。至少 3 组查询：

1. 领域大词 + 近两年热词（如 "LLM agent memory 2024"）
2. 候选方法名 / 技术词（如 "retrieval augmented generation evaluation"）
3. 交叉场景词（如 "large language model education"）

用户已有课题时，附带检索其相邻词，用于定位接续缺口。

## 方向发散（问方向）

归纳 3~5 个方向，每个方向按四要素展开：

- **做什么**：一句话说清研究内容
- **为什么现在可做**：落到本次检索到的具体文献趋势（新模型出现、数据集发布、既有方法在某场景失效等）
- **最小可行课题**：小到一篇论文能做完的具体任务
- **主要风险**：数据、算力或竞争上的最大障碍

纪律：方向必须"小到一篇论文能做完"，禁止拿领域名当方向（"做多模态"不是方向）；每个方向至少挂 1 篇真实检索文献作趋势证据。

## 论文推荐 + 接续工作

从检索结果挑 3~5 篇，优先满足：近 2~3 年、有公开数据或代码、范围可接续（非庞大系统工程）。每篇给出：

- **核心贡献**：一句话
- **他们没做的**：摘要或结论中作者自述的局限 / 未来工作
- **你可以接的**：具体接续点——换场景、补机制、组合另一篇的思路，落到"改什么、在什么数据上验证"

## 输出格式

```
## 方向建议：〈领域〉

1. **〈方向名〉**——做什么：…；为什么现在可做：…（证据：〈标题〉（2024））；
   最小可行课题：…；主要风险：…

## 推荐接续论文

- 〈标题〉（作者一作 et al.，2024，〈链接〉）
  ｜贡献：…｜他们没做：…｜你可以接：…（改 X，在 Y 数据上验证）
```

## 纪律

- 推荐与趋势判断必须基于本次检索结果，检索不到就明说覆盖不足，禁止凭记忆推荐
- 咨询结论引用论文一律〈标题〉+年份+链接，不用 [n] 编号（编号仅属于文献库）
- 用户决定动笔后，转 paper-drafting 流程，并用 register=true 重新检索把选定方向的关键文献登记入库
- 检索源覆盖有限（预印本与主要期刊会议为主）：结尾提示建议再人工核查 Google Scholar / DBLP，尤其对非 CS 领域
