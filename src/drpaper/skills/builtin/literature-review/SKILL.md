# 文献综述：多角度检索入库 + 主题式归纳成文

## 第一步：判定意图（三选一）

- **综述全文**：用户要"XX 课题的文献综述 / 研究现状综述"成文 → 走本流程，产出综述 docx。
- **单节相关工作**：用户在写论文，只要其中"相关工作 / 研究现状"一节 → 改走 paper-drafting，本 skill 不处理。
- **查新 / 求推荐**：意图是"这个课题有没有人做过"或"推荐该读什么" → 改走 novelty-check / research-guidance，本 skill 不处理。

## 第二步：检索规划（tier1 预算 3 次，一次不浪费）

硬约束：每次检索合并去重后最多返回 10 条；tier1（arXiv + OpenAlex）每次检索同时消耗两源各 1 次配额（各 3 次）→ 主动检索总预算 3 次；Semantic Scholar 仅在去重后不足目标条数时自动降级触发，不算主动预算。register=false 的摸底同样消耗配额。

1. **摸底**（1 次，register=false）：课题大词 + 近两年热词（如 "LLM agent memory 2024"），只看主题分布不入库——据此划出综述的 2~4 条主题路线，并记下各路线预计引用的代表文献。
2. **定向入库**（2 次，register=true，每次 max_results=10）：一次检索对应综述的一个主题节；查询用英文（检索源为英文库），组合"主题词 + 方法词 / 场景词 / 年份限定"；已入库文献重复命中只回编号，不占 token。
3. **入库即承诺**：register=true 的主题必须是确定要写的节；某次结果混入不打算引用的文献时，动笔前用 remove_papers 清理——编号会整体重排，收尾阶段清理需重写多节引用，代价极高。
4. **预期规模 15~20 篇**：大纲主题节按此设计，禁止贪多。入库不足 15 篇时收窄综述范围或换角度（对立观点、应用域）重组检索词，而非追加次数——配额已尽。

## 第三步：大纲与字数分配（begin_draft）

综述按主题路线组织，不是五段式论文：

```
# 〈课题〉研究综述
**摘要**：250 字左右（不按占比）
**关键词**：3~5 个（budget 填 0）
## 1 引言：背景、综述范围与文献选取口径（约 10%）
## 2~4 主题节：一条技术路线 / 一个问题维度一节，共 2~4 节（每节约 20%）
## 5 比较与讨论：跨路线横向对比综合（约 15%）
## 6 结论与研究空白（约 10%）
```

各节 budget = 用户目标字数 × 占比（四舍五入取整），全部节预算之和等于目标字数；用户未给字数时按 5000 字规划。主题节名必须具体到路线（如"基于记忆增强的 agent 方法"），禁止用"研究现状"这类空泛节名。

## 分节写法

- **按主题归纳，不按论文罗列**：一段一个论点，段内综合多篇文献（[1,3] 并引），禁止"某某提出了……某某又提出了……"式流水账。
- **引用密度**：每段至少 2~3 个 [n]；每个主题节消化对应检索路线入库文献的大半；全篇不得漏引任何入库文献。
- **对比综合**：3 条路线以上用 Markdown 表格横向对比，列取非数值维度（方法 / 任务场景 / 核心机制 / 主要局限），单元格来自文献摘要原文信息；表格后紧跟一段分析——路线差异的成因与各自适用边界，禁止只列不析。
- **研究空白**：每个主题节末尾点出该路线的局限；"比较与讨论"节把各节局限汇总成 2~3 条研究空白，落到"还没人做 / 做了但没验证"的具体表述，禁止笼统写"仍有待研究"。

## 纪律

- **文献真实性**：只引用检索返回的真实文献，[n] 与工具返回 index 一致；转述以摘要为据，禁止凭记忆补文献、编造作者或年份。
- 综述没有本文实验：禁止调用 estimate_metric；不转述文献中的具体实验数值，比较性断言（优于 / 领先 / 效果不足）一律挂 [n] 引用支撑。
- 一次性完成全部分节后才调用 finish_draft；返回 unused 文献时优先补引用（该文献确有内容可写），否则 remove_papers 后按新编号重新提交受影响的节，再 finish_draft。
- 工具调用轮次禁止输出任何叙述文字。
- 检索源以预印本与主要会议期刊为主，结尾提示建议人工核查 Google Scholar / DBLP，尤其非 CS 领域。
